# 3D reference — authored scenes, not generated slop

Why AI 3D reads fake, technically: missing subsurface scattering (skin = painted plastic), specular/diffuse confusion (matte gets mirror highlights, glossy lacks reflections), hard shadow terminators on curved surfaces, no global illumination (pure black-gray shadows, no bounce), averaged inconsistent lighting, statistical over-smoothing, perfect symmetry, and texture without fractal detail. The gloss is airbrushing for missing texture detail.

## The eight rules

1. **Silhouette first.** Block out big masses; if the hero object doesn't read as a black silhouette on a dark plane, no amount of detail saves it. Detail is spent only where the eye goes (rule 5 exists because of this one).
2. **Palette = the page palette.** The scene consumes the same token file as the web page: 2 neutrals + 1 accent. In Three.js the tokens become constants in one shared module — never per-scene hex. Every color has a place; a fourth hue needs a reason in writing.
3. **2–3 lights, direction declared in advance.** Key + fill/rim beats a pile of generic lights. Lighting is composition: declare the direction (the anchor often supplies it — "window light from upper-left") before touching materials.
4. **Real materials.** Roughness/metalness maps instead of uniform gloss; per-surface behavior (glazed ceramic ≠ matte stone ≠ brushed brass); soft light terminators on curves; ambient bounce tinting shadows; SSS where skin/wax demands it. In Blender: actual shader nodes, HDRI/area lighting. In Three.js: MeshPhysicalMaterial with clearcoat only where glaze justifies it.
5. **Detail as accent.** Polygon/texture budget goes where the viewer looks — rim, handle joint, coffee foam — not everywhere. Undirected detail piles are the #1 slop marker.
6. **Micro imperfection.** Natural asymmetry, slight off-center placement, camera-grain noise (rendered, not a painted overlay). Perfect symmetry + over-smoothing = artificiality markers.
7. **The 24px test.** A logo/mark from the 3D work must survive 24px in flat color. Gradient-orb marks collapse exactly there — design the flat silhouette first, light it second.
8. **Real-time budget.** Written up front in the system sheet, respected in review:

| Budget | Typical ceiling (web) |
|---|---|
| Draw calls | < 100 per scene |
| Triangles | < 200k total, < 50k for the hero object |
| Textures | ≤ 2048px, KTX2/basis where supported |
| Shadow maps | ≤ 1 directional + 1 point; no per-frame real-time shadows on mobile |
| Frame work | No object/GC allocation in the animation loop; pause rendering offscreen |

## Scene audit (feeds Phase 3)

Render 2 stills (hero angle + wide) to PNG and hand them to the visual-auditor with `audit.md` §3D. Failure signature to watch for: "looks fine in the hero shot" — audit the wide shot too; slop hides in the corners.
